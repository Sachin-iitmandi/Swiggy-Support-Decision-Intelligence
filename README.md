# Swiggy Support Decision Intelligence

**IIT Mandi AI/ML Capstone | Synthetic-data analysis | 100 marks**

This repository implements the four required parts of the Support capstone: resolution-time estimation and regression, escalation classification, ticket segmentation/PCA, and model comparison/architecture sizing.

> **Data notice:** All 800 records are synthetic and generated by the supplied capstone generator. They are not Swiggy customer records and do not describe Swiggy's actual performance.

## How to run

Use Python 3.10 or newer. From a clean clone, run these commands in order:

```bash
pip install -r requirements.txt
python generate_data.py
python part1.py
python part2.py
python part3.py
python part4.py
```

The scripts use only Python's standard library and NumPy. Run all commands from the repository root. The scripts regenerate the committed CSV and text files under `outputs/`.

The data generator should print:

```text
800 10 170 7cb48ef89914049d76954530b6482e04
```

## Part 1 findings

- The estimated mean resolution value is **8.9382 minutes** (95% interval 8.3026 to 9.5738). The test statistic is **z = 2.8930**, whose absolute value exceeds the two-tailed critical value **1.96**, so H0: μ = 8.0 is rejected at the 5% level. A Type I error here would mean concluding that the average resolution time differs from 8 minutes when the true population average is actually 8 minutes. The estimated gap is **0.9382 minutes**; operations should judge its practical importance against staffing and service-level costs.
- The required sample size for a 0.5-minute margin at 95% confidence is **1293**, compared with **800** records available. The current dataset is smaller than the sample size target for that precision.
- The gradient-descent slope gap is **0.0000**. With standardised X4, full-batch gradient descent converges toward the same least-squares line as the closed-form solution.
- The raw residual standard-deviation ratio is **3.7525**, showing a funnel because residual spread is much larger in the upper fitted-value half. The log-log ratio is **1.0396**, close to 1, so logging substantially reduces the changing spread.
- The multiple-regression coefficients above the required absolute-value cutoff of 0.05 are for **X4 account value** (1.1576), **X2 earlier ticket count** (0.0940), **X3 SLA consumed ratio** (0.1067) and **X6 reopened flag** (0.1518). Adjusted R² rises from **0.6561** for the log-log model to **0.7403** for the multiple model, suggesting added predictors improve in-sample fit.

## Part 2 findings

- The 200-update losses from lowest to highest are η = 1.0 (**0.3703**), η = 0.1 (**0.3776**), and η = 0.01 (**0.5091**). The smaller learning rate makes slower progress; the larger rate performs best among those tested for this run.
- The three largest absolute logistic weights are **X3 SLA consumed ratio** (0.9013), **X1 customer tenure** (-0.5554) and **X2 earlier ticket count** (0.5505). The largest odds ratio is X3 at **2.4629**: a one-training-standard-deviation increase in SLA consumed ratio multiplies estimated escalation odds by about 2.46, holding other predictors fixed.
- The all-negative baseline accuracy is **0.7875**, while logistic accuracy at τ = 0.5 is **0.8042**. Accuracy alone is weak because only 51 of 240 test tickets escalated, so predicting every ticket as non-escalated already looks reasonably accurate. Lowering τ from 0.5 to 0.3 raises recall from **0.4706** to **0.7451**, while precision falls from **0.5455** to **0.4634**.
- At τ = 0.3, logistic regression has **F1 = 0.5714** and **recall = 0.7451**; KNN (best K = 5) has **F1 = 0.3696** and **recall = 0.3333**.
- I would pilot logistic regression with training-selected threshold **τ = 0.1500**. Test cost is **INR 6050**, versus **INR 11800** at τ = 0.5 and **INR 20400** if nobody is flagged. The threshold was chosen on training rows to avoid tuning against held-out test outcomes.

## Part 3 findings

- Successive WCSS drops are **659.8282**, **108.0739**, **171.0575**, and **45.5466**. The elbow rule selects **K = 3** because the K=3 to K=4 drop is less than half the preceding drop. The specified starting rows give a reproducible solution, not necessarily the global optimum.
- **Segment A – Low-friction / steady tickets:** 322 records, mean earlier-ticket count 1.9503, SLA consumption 0.2250 and escalation rate 1.86%; keep these in the standard support flow. **Segment B – Repeat-contact / high-value tickets:** 255 records, mean earlier-ticket count 6.0706, account value INR 28.7192 thousand and escalation rate 23.53%; route repeat contacts with full history and ownership continuity. **Segment C – SLA-pressure tickets:** 223 records, mean SLA consumption 0.7118, satisfaction 38.5215 and escalation rate **46.64%**, the highest; trigger proactive supervisor review.
- At the largest-gap cut, **single linkage** gives four clusters: `{E1}`, `{E2,E3,E6}`, `{E4}`, `{E5}`. **Complete linkage** gives two clusters: `{E1,E4,E5}` and `{E2,E3,E6}`. Single linkage can join clusters through one close bridge (chaining); complete linkage requires all cross-cluster pairs to be close, so it delays the final merge and creates a different largest gap.
- The standardised PCA mean vector is zero. PC1 is driven mainly by positive X1 (+0.5317) and X5 (+0.4418), and negative X3 (−0.5187) and X2 (−0.4100); X4 contributes moderately (−0.2916). **Three components** retain at least 80% of variance (86.16%). ## Part 4 findings

- **S4 (X1 ≤ 24)** is best by both information gain and Gini gain (root entropy 0.7462, root Gini 0.3347). It produces the strongest impurity reduction among the four candidate splits. A tree grown until every leaf is pure can memorise noise; a maximum-depth limit or minimum-leaf-size rule helps control overfitting.
- Logistic regression is strongest by test F1 (**0.5714**, recall **0.7451**). The stump has F1 0.5532 and recall 0.7647; KNN has F1 0.3696 and recall 0.3333; hard voting has F1 0.5344; soft voting has F1 0.5507. Combining models did not improve F1 over logistic regression on this split.
- After round 1 normalisation, the two h1-misclassified observations carry combined weight **0.5000**. Round 2 gives h2 greater influence because its weighted error is 0.1667 and α₂ = 0.8047 exceeds α₁ = 0.5493.

## Model-choice memo

**To: Head of Customer-Support Operations**  
**Subject: Structured ticket-escalation model recommendation**

I recommend piloting the from-scratch logistic-regression classifier for structured ticket triage, using the training-selected threshold of **0.15**. On the held-out test set, logistic regression at τ=0.3 achieved F1 **0.5714** and recall **0.7451**, outperforming KNN's F1 **0.3696** and recall **0.3333**. The cost-optimised threshold of 0.15 produced a test cost of **INR 6,050**, compared with **INR 11,800** at τ=0.5 and **INR 20,400** when no tickets are flagged. The model is interpretable and inexpensive to score, and can support a supervisor-review queue. The key evidence risk is that the dataset is synthetic and evaluation uses one fixed train/test split, so the results do not establish performance on real operational traffic. I would prioritise **Model B (ticket-text RNN)** only as a later research project after the structured model is validated and a representative, privacy-approved labelled text dataset is available; it is not a prerequisite for this pilot.

## Limitations

1. **Synthetic data:** the generated patterns cannot be assumed to match real support operations.
2. **Single fixed split:** classification metrics may vary on another sample; repeated or time-based validation would provide stronger evidence.
3. **Small positive test group:** only 51 of 240 test tickets are escalations, so a few changed predictions can noticeably alter metrics.
4. **Limited feature set:** ticket text, order context, agent workload and time-of-day signals are not modelled.
5. **Associations are not causes:** coefficients and segment profiles should not be interpreted as causal effects.
